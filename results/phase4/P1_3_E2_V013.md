## 1. The change

The branch is `lifecycle/level3` of the v0.13.8 clone, in the worktree `impl/wt-l3-v0138`. It starts from that line's
E1 release, `lifecycle/level2` (`588e639`, ACL v0.4.2).

| Commit | Change |
|---|---|
| `c5c787f` | **ACL v0.4.3 with E2.** Main's E2 (`lifecycle/level3` `3d085806`): `retireAccountWithSig`, the same checks in the same order, the same EIP-712 domain separator and type hash, the ERC-165 id `0x4b9ec076`; `retireAccount()` and the certificate share `_retire()`. The bodies of both functions are byte-identical to main's. Reinitializer 8, `reinitializeV7()` (E2 adds no state). The Foundry profile turns the optimizer on. The upgrade matrix and the version strings follow (details below) |
| `90dea52` | **The TC19 and TC24 tests**, main's `0d02f3e0` copied unchanged: `ACLRetirementCertificate.t.sol` (13 tests) and `retirement/CertificateMocks.sol` |

**The upgrade matrix on this line:**
- The four v0.4.1 → v0.4.2 cases now target a v0.4.2 fixture. It was generated by `impl/harness/level0/make_fixtures.py` from `lifecycle/level2`'s `ACL.sol` (git blob `be182ded`).
- **U9:** an upgrade from v0.4.2 to v0.4.3 keeps E1's state (a confirmed successor, a pending designation, a raised delay), and a certificate works right after it.
- `reinitializeV7` follows Zama's pattern: from version 7 it lands on 8, and a second call reverts.

**The ERC-165 fuzz test** now excludes every id the ACL declares, as on main (`5cd12ed5`). The fuzzer draws 4-byte constants from the bytecode and found the new id `0x4b9ec076`. The same test on this line's E1 branch does not exclude E1's ids either. It has passed so far by chance; this is a test-only flaw, and the mechanism is not affected.

- **The unoptimized profile was never deployable.** Phase 3 reported the E1 ACL 660 bytes over the limit in it; this build measures 788. Zama's own `FHEVMExecutor` and `HCULimit` are far over the limit there too.

## Reproduction (from `fhe-authority-lifecycle/`)

```bash
node impl/harness/level2/link_deps.mjs impl wt-l3-v0138
cd impl/wt-l3-v0138/host-contracts && FOUNDRY_ISOLATE=false forge test
FOUNDRY_ISOLATE=false forge build --sizes --skip test --skip script
FOUNDRY_OPTIMIZER=false FOUNDRY_ISOLATE=false forge build --sizes --skip test --skip script --out /tmp/noopt
```

`link_deps.mjs` makes junctions; Foundry 1.8.5 refuses them ("path should be a child of root"). As for the 0.14 line
(D29), the worktree's `host-contracts/node_modules` and `dependencies` are therefore copies (D40).

The copies are:
- OpenZeppelin `contracts`, `contracts-upgradeable` and `foundry-upgrades`;
- `encrypted-types`;
- forge-std 1.11.0.
